# Anthos 4.3 — portable story quality hardening (locked 2026-11-23)

**Status:** Implemented as regression infrastructure in draft PR #135. NOT a pass for all episodes and NOT a production deployment. Remain within the existing 4.3 engine; do not start a parallel 4.4 engine.

## Four locked priorities, in order

1. **Humanlike character dialogue.** Messages are grounded in each fictional character's enduring motivations, flaws and real private-chat relationship. A character must not call the friend “the coach,” use scoring/AI language, or mechanically narrate a success. Character choice, humor and disagreement must feel personal.
2. **Semantic story continuity.** Every episode must author its own world and state timeline with verified events, object status and prohibited implications. A joke cannot imply an already completed purchase has not happened. Attempts to contradict a canonical statement fail validation and receive a bounded regeneration; approved facts remain authoritative.
3. **Coaching-contingent consequences.** Advice is not action; verified character decisions may follow, partly follow, resist or reject. New event IDs, emotional consequences and evidence movement belong in the canonical ledger. No spontaneous advancement through time or repeated point credits.
4. **Auditable 8/10 quality review.** Preserve the 100-turn live-model pilot's complete dialogue, role, advice, provider receipt, events, before/after world state, attribution, retries, warnings, skill references and human-source quotes. All ten editorial dimensions require direct transcript citation, plus separate non-averagable hard checks.

## Reusable story-quality contract

The new pure module `lib/anthos-story-quality.mjs` supplies `assertStoryQualityContract`, `reviewStoryReply` and the currently approved microwave world. An episode-specific contract must identify:
- `version` and stable `episodeId`
- `world.who`, `world.what`, `world.where`, `world.when`, `world.why`
- `characterVoices.jack` and `characterVoices.jill`, each with `voice`, `coreNeed`, `flaw`, `relationship`
- an explicit `objects` inventory (empty array if no tracked object)
- `invariants` containing stable IDs, established facts and example prohibited implications

The 4.3 private reply generator receives world/persona data, checks the whole reply (including implied facts in jokes), rejects fourth-wall role leaks, flags highly overlapping messages and records advisory signals with each turn. A missing or malformed contract fails closed. The existing microwave source remains the only production-shaped 4.3 scenario currently authorized by `buildConversation43`; a new story MUST NOT inherit the microwave character/world constraints. Adding its contract alone is insufficient to create its action/state machine.

### Invariants are a floor, not an AI guarantee

The deterministic validator catches explicitly authored phrase patterns and exact repetition. It **cannot** prove all human-language implications are coherent, classify all sarcasm, or certify rich characterization. Author an adversarial phrase set for every new scenario and independently review complete real-model transcripts. Do not lower the 8/10 standard to make tests green.

## Verification and promotion ladder

1. **Pure tests:** multiple unrelated hypothetical episode contracts (microwave, vacation/train, birthday/cake), false implication rejection, natural joke acceptance, role leak rejection, null contract held, repetition flagged.
2. **Actual 4.3 handler path:** invalid joke and fourth-wall regression exercises, regeneration before delivery, provenance recorded.
3. **Same frozen microwave ten-couple benchmark:** run unchanged constructive and difficult coaching paths; compare before/after source-linked scenes, actions and independent quality ratings.
4. **One fully authored different story:** write its own decision/action/knowledge graph and voice contract, then test alternating/private roles, rumors, humor, completed-vs-planned actions, resistance and evidence integrity. This requires further implementation: `buildConversation43` currently intentionally restricts the pilot to the microwave story.
5. **30 scenario/skill combinations**, then **all 120 authored stories**, with adversarial coach variants and repeated stochastic model samples after every material code/model revision.
6. **G8 certification:** ten independent couples × five days × two character streams, 100 verified real-model response IDs and zero fallback; each couple's ten editorial dimensions mean >=8, every dimension >=7, explicit transcript citations for all ten; pass `LIVE43_HARD_CHECKS` for repeated events, unverified actions, double counting, skill evidence, consent/respect and couple isolation. Any blocker means no merge.

The existing report verifier and production release gate reject missing, offline or unreviewed real-model evidence. The original Nov 22/23 100-turn smoke pass remains an engineering baseline and **does not certify** this subsequent code.

## Important boundaries

- The existing 4.3 action interpreter, saved Studio data, model configured key, JJ4 rooms, Supabase and Telnyx are NOT replaced by this work.
- PR #135 remains draft; G1–G7 are partial and G8 blocked. A successful focused GitHub test is code evidence, not customer/1,000-couple release evidence.
- The Insight Atlas is shared by authenticated members of the correct couple during and after episodes: no separate intra-couple disclosure/consent unlock step. Couple isolation and consent/respect within fictional relationship content remain separate requirements.
- Full scripted OpenAI prompt exchange may contain sensitive data and secrets. QA artifacts must be stored protected; do not publish private coaching transcripts or provider credentials in GitHub logs.
