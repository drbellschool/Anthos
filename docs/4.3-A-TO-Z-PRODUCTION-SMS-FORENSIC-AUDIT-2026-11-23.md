# Anthos 4.3 — A-to-Z production SMS forensic audit
**Reviewed November 23, 2026 · incident: What Makes Us Feel Close · production source commit `f50f83b0`**

## Decision
**FAIL — next live pilot NOT READY.** The live system loaded a real 4.3 episode graph and generated a validated OpenAI SMS reply, but its temporal orchestration was still controlled by reusable 4.2 day/scene machinery. That machinery advanced six simulated days without requiring character enactment or reciprocal coaching, and the graph adapter subsequently repeated the original unmodified premise. The handset pilot did not demonstrate the intended 4.3 free-text, two-character, consequential exchange.

**Scope:** The user explicitly requests an end-to-end exchange/process audit, not revisions to narrative, dialogue lines, humor premise or skills. Do not rewrite episode data, unlock old prompts, introduce a new 4.4 engine, initiate SMS or imply certification.

- Correct environment: production `anthos.love`; Vercel `threefold-preview`, deployed SHA `f50f83b0fe3dbb73aa4a1c7a4cc1c709a95c595b`, sourced from draft PR #135's feature branch.

- Incoming signed provider event log has **one completed event and one error**. The second event's exact underlying exception cannot be recovered from the retained per-event log. The event body is deliberately not retained. Vercel historical runtime errors were unavailable/empty for that narrow interval. Avoid assigning an unsupported cause.
- The sole live character reply used third-person coach language, despite the model prompt explicitly prohibiting it. `reviewStoryReply`'s lexical blocker handles "the/my/your coach" but not the observed bare "Coach says" pattern. This is a quality guard gap, not the primary orchestration failure.

- No authenticated `anthos_atlas_episodes` row or `anthos_atlas_room_claims` exists for this live room: the intended four-subject persistent score/long-term-memory feedback path did **not** participate in this live exchange.
- To preserve the conversation and prevent delayed sends after subsequent bug fixes, **only this failed pilot's two SMS session rows were superseded** (not STOP/opt-out). Both confirmed `superseded_at IS NOT NULL`; their registration consent and canonical transcript remain unchanged. No new SMS or pilot run was initiated by this audit.

## Why the automated green suite didn't protect the live pilot
- Focused CI at the deployed SHA: **132/132 passed**, but those are source-unit/in-memory mock checks. The separate full-site job and the **intentional release gate are red**.
- The earlier **100 real OpenAI responses** were from a different historical microwave revision and fictional scripted couples; NOT this second episode, NOT live Telnyx, NOT this deployed commit, NOT a ten-person independent human review.
- `tests/jj43-random-episode-transfer.test.mjs` demonstrates coherent ten-turn transitions by supplying *selected pre-authored coaching phrases and mock replies* across five days. It does not model a single genuine coach reply and silence.
- `tests/jj41-sms-webhook-integration.test.mjs` checks 10-minute advancement as an expected **success** without requiring progress. That test encoded the failed experience as intended behavior.
- The microwave full-week SMS test covers its Saturday closure; **the second-episode SMS test stops after the first reply** and thus misses the divergent graph closure path.
- No test exercises a real provider failure at a signed inbound webhook followed by automatic durable retry/delivery confirmation.
- No regression asserts that user advice can create a new canonical action when semantically equivalent to an authored option but not textually matching its cues.

## Fault hierarchy — fix **process**, not episode narrative
1. **P0 · Causal orchestration:** Replace time-only progression with 4.3 conversation/state prerequisites: eligible check-ins are not automatic scene replacements. After real advice, the character actually chooses and the new situation follows from the event. Silence may produce a natural *status check* but must not imply a completed story.
2. **P0 · Semantic action + agency:** Use semantic intent interpretation and a bounded, character-dependent decision (follow, partial, resist, reject). Preserve actual authored story facts and the same twelve rules; do not force the user's wording to match hidden cues. Unrecognized advice should be actively discussed or clarified, not silently converted into no-op.
3. **P0 · Reliable inbound/outbound:** Persist inbound events and terminal/failed status separately; retry errors using stable request keys and no duplicate actions. Avoid long provider generations holding a signed webhook request with no durable acknowledgment. Record safe response errors and provider delivery status.
4. **P0 · Correct Sophia:** Pass the same ledger shape to the closing logic as to the normal scene renderer; test the SECOND episode's Saturday, not only microwave. No closing after zero interaction simply because the timer elapsed.
5. **P0 · Actual prompt continuity:** Use the latest verified event, scene state and character-specific prior messages when constructing new check-ins, not the unmodified role opening every day.
6. **P1 · Tie Atlas to authenticated couple:** Existing tables are not enough. Explicitly claim the pilot against the right authenticated couple before expecting score/memory influence. Persist/recall four-subject real evidence; never infer ownership from SMS alone.
7. **P1 · Live human-quality contract:** Reject "Coach says" and other fourth-wall variants; measure response quality and causal context without writing new story scripts. Review both private lanes, varied advice, unreplied messages and all 10 ratings with directly cited evidence.
8. **P1 · Monitoring and release quality:** Add red tests that replay the real incident's cadence (one early coaching turn, a second failed message, silent spouse, 10-minute clock) plus a real OpenAI/Telnyx proof. Do not promote as 8/10 because unit tests pass.
