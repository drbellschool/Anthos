# Anthos 4.3 — Full-character-voice generator, not an AI prefix

**Implementation date:** 2026-11-22  
**Status:** Integrated in draft PR #135, model-backed mocked tests passed. Full real-model quality certification remains BLOCKED.

## Existing flow now

1. Read exact previously committed story facts and the specific coach message.
2. Classify the actual suggestion and character's likelihood of adopting/resisting it; no unverified reported instructions can commit actions.
3. Compute and validate one canonical event; persist a unique event identity; the state and score ledger remain independent of generated wording.
4. **Use the existing Responses API** with the existing configured model/key to write the *entire* Jack/Jill reply as a natural SMS to the private coach. No canned sentence appended. Context includes character flaws, motivations, the actual coaching, pre/post world state, evidence about any committed action, past own-coach replies, developmental tendency, unresolved tension, and source-verified memories.
5. Require exact coach-to-reply grounding anchors in the generated structured output, reject replies that introduce additional actions or unsupported partner reactions, repeat earlier character text, invent repair price, repair completion, another purchase or a new shop call. A benign joke must be attempted or explicitly addressed.
6. On invalid draft, regenerate once with concrete validator feedback; if still invalid/unavailable, use the existing safe fallback and record `replySource`, `replyModelAttempts`, `replyValidationIssue`. Only real canonical actions are scored; a generated sentence cannot award points.
7. Continue using the two existing Jack/Jill conversations, shared event ledger and Insight Atlas; no new Anthos engine, public API, database tables, keys or new AI provider.

Do **not** silently copy sensitive production secrets into broadly accessible previews or claim this is a live-AI demonstration. `status().voiceMode` reports `full-model` or `verified-fallback` without disclosing credentials; `/pilot-v4/` now displays that diagnostic to the tester.

## Mandatory pre-pilot contract — November 22, 2026 (enforced)

After the 10-couple rehearsal exposed 31% distinct canned replies, we locked the following requirements into the actual 4.3 implementation and release gate:

1. **No credential, no live pilot:** `ANTHOS_QA_LIVE=1` forces the existing `tests/atlas-diverse-couples-pilot.test.mjs` to call `assertLivePilotKey43` before any simulated turn. It will not silently fall back. Each character turn has `requireModelVoice=true`; unavailable or twice-invalid generation rejects the pilot rather than returning canned dialogue. Production user-facing fallback is not mislabeled as passing QA.
2. **Verifiable model source:** `replySource=model-validated`, 1–2 attempts, provider model and unique `resp_...` response ID are required for every one of the 100 messages. Model IDs are not proof by themselves; the human quality reviewer must compare protected execution logs with the real run and cannot certify a fixture or fabricated report.
3. **Factual hard block, creative freedom:** Verified purchase, box, repair and interpersonal events cannot be contradicted or invented. An appropriate joke may be dry, metaphorical or an explained refusal; the model must indicate `humorResponse` and cite exact `humorEvidence` appearing in its reply. There is no hard-coded list of words a joke must contain. Human reviewers judge whether this was genuinely responsive. The bounded response wait is 18 seconds instead of 8.5, with a maximum of two attempts and a larger 440-token output allowance.
4. **Eight-out-of-ten is an evidence test:** `lib/atlas-live-qa-contract.mjs` verifies ten different couples, all 5 days, both Jack/Jill streams, no continuity failures, three weekly skill opportunities, all messages model-authored, unique response receipts and citation-bearing human scores for ten dimensions. Each couple must average at least **8/10**, each dimension must be at least **7**, and any critical violation fails. `scripts/verify-atlas-live-pilot.mjs` rejects absent, offline, incomplete, or unreviewed reports; `scripts/verify-atlas-release.mjs` requires the same proof even if someone marks G1–G8 verified.
5. **No launch implication:** The key is currently production-only and inaccessible to the protected test executor, so a genuine live-model run remains **BLOCKED**. Offline story mechanics and mocked Responses fixtures are useful regression tests, **not** certified ten-couple natural dialogue or an 8/10 launch.

To run real QA after the existing key is available through an approved protected execution mechanism (not by exposing it to all previews): `ANTHOS_QA_LIVE=1 ANTHOS_QA_OUTPUT_PATH=/protected/pilot.json node --test tests/atlas-diverse-couples-pilot.test.mjs`; then conduct cited human reviews using `lib/atlas-live-qa-contract.mjs`, attach the review file, and run `node scripts/verify-atlas-live-pilot.mjs /protected/pilot.json`. The latter MUST reject a run that lacks authentic reviewed evidence.
